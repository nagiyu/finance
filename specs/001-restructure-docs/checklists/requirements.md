# 要件チェックリスト

## 概要

本チェックリストは、要件定義の品質を確認するための項目を定義します。各要件が適切に記述され、実装可能であることを確認するために使用します。

---

## 1. 要件の明確性

- [ ] 要件が明確かつ具体的に記述されている
- [ ] 曖昧な表現（「適切な」「必要に応じて」など）が排除されている
- [ ] 専門用語が定義されている、または一般的に理解可能である
- [ ] 要件の範囲（スコープ）が明確に定義されている

## 2. 要件の完全性

- [ ] すべての機能要件が網羅されている
- [ ] すべての非機能要件が網羅されている
- [ ] 前提条件と制約が明記されている
- [ ] 例外ケースとエラーハンドリングが考慮されている

## 3. 要件の一貫性

- [ ] 要件間で矛盾がない
- [ ] 用語が統一されている
- [ ] 既存のシステム・ドキュメントとの整合性がある
- [ ] 優先順位が明確に設定されている

## 4. 要件の検証可能性

- [ ] 各要件に対して受入基準が定義されている
- [ ] 受入基準が測定可能である
- [ ] テスト方法が明確である
- [ ] 成功・失敗の判定基準が明確である

## 5. 要件のトレーサビリティ

- [ ] 要件に一意の識別子（ID）が付与されている
- [ ] 要件の出典（ステークホルダー、ドキュメント等）が記録されている
- [ ] 関連する要件間のリンクが明示されている
- [ ] 変更履歴が追跡可能である

## 6. 実装可能性

- [ ] 技術的に実現可能である
- [ ] リソース（時間、予算、人員）の制約内で実現可能である
- [ ] 依存関係が明確に定義されている
- [ ] リスクと対策が検討されている

## 7. ユーザビリティ

- [ ] ユーザーの視点で要件が記述されている
- [ ] ユーザーストーリーまたはユースケースが適切に定義されている
- [ ] アクセシビリティが考慮されている
- [ ] ユーザーフィードバックが反映されている

## 8. セキュリティ

- [ ] セキュリティ要件が明記されている
- [ ] 認証・認可の要件が定義されている
- [ ] データ保護の要件が定義されている
- [ ] コンプライアンス要件が考慮されている

---

## 使用方法

1. 各セクションのチェック項目を確認する
2. 該当する項目にチェックを入れる（`[ ]` → `[x]`）
3. チェックできない項目については、理由を記録し改善する
4. すべての必須項目がチェックされた時点で要件定義完了とする

## 備考

- 本チェックリストはプロジェクトの特性に応じてカスタマイズ可能です
- 定期的にチェックリストの有効性を見直し、改善してください
