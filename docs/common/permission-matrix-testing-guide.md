# 権限マトリックス テストガイド

## 概要

本ドキュメントは、権限マトリックスの更新と反映をテストするための手順を説明します。

## テストシナリオ

### シナリオ1: 権限マトリックスの更新と永続化

**目的**: 権限マトリックスが正しくデータベースに保存され、再読み込み後も維持されることを確認する。

**手順**:
1. 管理者アカウントでログインする
2. `/permission-admin` にアクセスする
3. 任意の機能の権限を変更する（例：STOCK_CHART の GUEST 権限を NONE から VIEW に変更）
4. 「保存」ボタンをクリックする
5. 保存成功のメッセージが表示されることを確認する
6. ページをリロードする（F5 または Ctrl+R）
7. 変更した権限が維持されていることを確認する

**期待結果**:
- ✅ 権限の変更が保存される
- ✅ ページリロード後も変更が保持される
- ✅ エラーメッセージが表示されない

### シナリオ2: ゲストユーザーの権限変更反映（STOCK_CHART）

**目的**: STOCK_CHART の GUEST 権限を VIEW に変更した場合、ゲストユーザーが株価チャートを閲覧できることを確認する。

**前提条件**: STOCK_CHART の GUEST 権限が NONE に設定されている（デフォルト状態）

**手順**:
1. **ゲストでのアクセス確認**:
   - ログアウト状態（ゲスト）でホームページ `/` にアクセスする
   - 「この機能へのアクセス権限がありません。」というメッセージが表示されることを確認する

2. **管理者による権限変更**:
   - 管理者アカウントでログインする
   - `/permission-admin` にアクセスする
   - STOCK_CHART の GUEST 権限を NONE から VIEW に変更する
   - 「保存」ボタンをクリックする
   - 保存成功のメッセージが表示されることを確認する

3. **権限変更後のゲストアクセス確認**:
   - ログアウトする
   - 新しいブラウザタブまたはシークレットモード/プライベートウィンドウで `/` にアクセスする
   - 株価チャートが表示されることを確認する
   - エラーメッセージが表示されないことを確認する

**期待結果**:
- ✅ 権限変更前: ゲストユーザーはアクセス拒否される
- ✅ 権限変更後: ゲストユーザーが株価チャートを閲覧できる
- ✅ 権限変更はすぐに反映される（最大5分のキャッシュTTL内）

### シナリオ3: キャッシュの動作確認

**目的**: 権限マトリックスのキャッシュが正しく機能することを確認する。

**手順**:
1. 管理者でログインし、`/permission-admin` にアクセスする
2. ブラウザの開発者ツール（F12）を開き、ネットワークタブを表示する
3. ページをリロードして、`/api/permission-matrix` へのリクエストを確認する
4. 5分以内に再度ページをリロードする
5. APIリクエストの数を確認する

**期待結果**:
- ✅ 初回読み込み時にDBから権限マトリックスを取得する
- ✅ キャッシュTTL（5分）内の再読み込みではDBアクセスが発生しない（キャッシュを使用）
- ✅ 5分経過後の再読み込みでは新たにDBから取得する

### シナリオ4: キャッシュ無効化の動作確認

**目的**: 権限マトリックスを更新した際、キャッシュが正しく無効化されることを確認する。

**手順**:
1. 管理者でログインし、`/permission-admin` にアクセスする
2. 権限を変更して「保存」ボタンをクリックする
3. 保存成功後、表示されている権限が更新されていることを確認する
4. 別のブラウザタブで `/` にアクセスする
5. 変更した権限が反映されていることを確認する（例：ゲスト権限を変更した場合、ゲストとしてアクセスして確認）

**期待結果**:
- ✅ 権限保存時にキャッシュがクリアされる
- ✅ 保存後すぐに新しい権限が反映される
- ✅ 他のページやAPIでも新しい権限が使用される

## トラブルシューティング

### 問題: 権限変更が反映されない

**可能性のある原因**:
1. キャッシュが古い状態で保持されている
2. データベースへの保存が失敗している
3. ブラウザキャッシュが古いページを表示している

**解決方法**:
1. ブラウザのキャッシュをクリアする（Ctrl+Shift+Delete）
2. シークレットモード/プライベートウィンドウで再度アクセスする
3. サーバーログを確認してエラーが発生していないか確認する
4. DynamoDBコンソールで `PermissionMatrix` レコードが正しく更新されているか確認する

### 問題: ゲストユーザーの権限変更が反映されない

**可能性のある原因**:
1. キャッシュTTL（5分）内でキャッシュが残っている
2. セッション情報が古い状態で保持されている

**解決方法**:
1. 5分待ってから再度アクセスする
2. 完全に新しいブラウザセッション（シークレットモード/プライベートウィンドウ）でアクセスする
3. サーバーを再起動してキャッシュをクリアする（開発環境の場合）

## パフォーマンス確認

### キャッシュ効果の測定

権限マトリックスのキャッシュによるパフォーマンス改善を確認する方法：

1. **ブラウザ開発者ツールを使用**:
   - ネットワークタブで `/api/auth/check-permission` や `/api/permission-matrix` へのリクエストを監視
   - レスポンス時間を記録
   - キャッシュヒット時とキャッシュミス時のレスポンス時間を比較

2. **サーバーログで確認**:
   - DynamoDBへのアクセスログを確認
   - キャッシュヒット率を計算
   - DB読み取り回数の削減を確認

**期待される改善**:
- キャッシュヒット時のレスポンス時間: < 10ms
- キャッシュミス時のレスポンス時間: 50-200ms（DBアクセス含む）
- DB読み取り回数: 最大99%削減（キャッシュTTL内）

## まとめ

本テストガイドに従って権限マトリックスの動作を検証することで、以下を確認できます：

- ✅ 権限マトリックスの更新と永続化
- ✅ 権限変更の即時反映
- ✅ キャッシュの正常動作
- ✅ パフォーマンスの改善

定期的にこれらのテストを実行して、システムの正常性を確認してください。
