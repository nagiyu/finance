# 移行計画 — ドキュメント構造化とドキュメント駆動開発の整備

**Feature Branch**: `001-restructure-docs`  
**Created**: 2025-11-27  
**Last Updated**: 2025-11-27  
**Status**: Draft

## 概要

このドキュメントは、`docs/` 配下へのドキュメント移行計画を記載します。既存ドキュメントの調査結果に基づき、移行対象一覧・優先度・統合先・担当者を管理します。

## 方針

- **統合優先**: 重複ドキュメントは統合し、古いものは削除する。
- **履歴保持**: 削除前に統合先を明確化し、変更履歴と理由を本ファイルに記録する。
- **レビュー必須**: 統合・削除はレビューと担当者承認を必須とする（PR で明示）。
- **Git 履歴活用**: 通常は Git の履歴で過去バージョンを追えるため、リポジトリ内に冗長なアーカイブを残さない。

## 移行対象一覧

以下の表に移行対象のドキュメントを記載します。

| ID | 現在のパス | 移行先パス | アクション | 優先度 | 担当者 | ステータス | 備考 |
|----|-----------|-----------|-----------|--------|--------|-----------|------|
| M001 | (例) `finance/README.md` | `docs/finance/README.md` | 移動 | High | @owner | 未着手 | ハブページとして整備 |
| M002 | (例) `client/finance/docs/setup.md` | `docs/client/setup.md` | 統合 | Medium | @owner | 未着手 | 既存ドキュメントと統合 |
| M003 | (例) `server/docs/api.md` | `docs/server/api.md` | 移動 | Low | @owner | 未着手 | - |

### ステータス凡例

- **未着手**: 移行作業が開始されていない
- **進行中**: 移行作業を実施中
- **レビュー中**: PR が作成されレビュー待ち
- **完了**: 移行が完了しマージ済み
- **保留**: 何らかの理由で保留中

### アクション凡例

- **移動**: ファイルを新しいパスに移動（frontmatter 追加含む）
- **統合**: 複数のドキュメントを1つに統合
- **アーカイブ**: 重要な履歴がある場合のみアーカイブ
- **削除**: 不要なドキュメントを削除
- **更新**: 既存の場所でコンテンツを更新

## 移行ログ

移行作業の履歴を時系列で記録します。

| 日付 | ID | 変更内容 | PR リンク | 理由 |
|------|-----|---------|----------|------|
| YYYY-MM-DD | M001 | (例) `finance/README.md` を `docs/finance/README.md` へ移動 | #123 | ハブページとして統合 |

## 優先度の基準

- **High**: 主要コンポーネント（MyTicker, Finance API 等）の基盤ドキュメント
- **Medium**: 開発ガイドやセットアップ手順
- **Low**: 補足的なドキュメントや参照資料

## 次のステップ

1. 既存ドキュメントの調査を実施し、移行対象一覧を更新する
2. 優先度 High の項目から順次移行を開始する
3. 各移行作業は PR を作成しレビューを受ける
4. 移行完了後、移行ログを更新する
